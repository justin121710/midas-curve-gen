新架構:一切都是「空間線型組」

目標是補 midas 不擅長的空間線型建模,不是產生一座完整的橋。
一組 = 一串節點 + 連接它們的元素

組與組預設互不相干,不共用節點、不繼承方向、不共用編號。
每一組自己決定:起點與終點(全域座標直接給)、形狀、要切幾個節點、元素種類/材料/斷面、群組名稱、編號起始。
要讓兩組產生關係,必須明確加一個「連接組」——這是唯一的耦合方式。

型別:兩族,共 8 種

族型別怎麼定義取代原本的
幾何直線起點 → 終點直線段落
幾何圓弧起點 → 終點 + 半徑 + 偏向 + 優/劣弧
或 起點 + 圓心 + 轉角		圓弧段落
幾何懸垂曲線起點 → 終點 + 垂度(拋物線 / 懸鏈線)主纜、纜索垂度
幾何螺旋線起點 + 圓心軸 + 半徑 + 螺距 + 圈數新增(midas 最痛的一項)
幾何線形鏈起點 + 方位角 + 段落串(直線/圓弧/緩和)
可選:縱斷面 VPI、樁號		主線 + 縱斷面
幾何偏置依附某一組,橫向 d / 垂直 h偏置線
連接組對組逐節點連接兩組(需節點數相同)橫梁
連接組對高程每個節點垂直連到指定高程,產生新節點吊索
連接點對組一個點連到某組的所有節點(扇形)斜張索
「線形鏈」是唯一保留內部串接與樁號的型別——道路線形本來就是那樣定義的。其餘型別一律用起終點直接放在空間裡。

這個改動實際刪掉了什麼

原本新架構
3D 剛體轉換模組
基準點/方向點/方位角/滾轉,7 個欄位		 大部分不需要了。懸垂曲線直接給兩個全域端點就定位完成,不必先在局部座標算完再轉。
只在「線形鏈」保留一個進階選項:整組平移旋轉。
主纜模組的 24 個欄位
跨徑/鞍座高程/索面數/索面間距/吊索/轉換…		 拆成 2 個懸垂曲線組(左右索面,各自給端點)+ 1 個組對高程(吊索)。每組欄位不到 8 個,而且全部是通用欄位。
「主線」的特殊地位沒有主線了。線形鏈只是其中一種組,可以有 0 個或 5 個。
全域縱斷面變成「線形鏈」型別自己的屬性。其他型別用不到。
橫梁 / 吊索 / 斜張索三個橋梁名詞 → 連接族的 3 種通用型別,元素種類自己設。
編號散在 6 處每組自己一個號段,樹上直接顯示;另有一張總表可一次檢視衝突。
要你確認的三件事:
  • 圓弧用「起點→終點+半徑」會有兩組解(左/右 × 優弧/劣弧),所以要多兩個開關。你也可以選「起點+圓心+轉角」。兩種都給,還是只留一種?
  • 「線形鏈」要不要保留? 它是唯一還帶樁號、緩和曲線、縱斷面的型別。如果你的用途已經不需要道路線形,可以整個拿掉,App 會再小一圈。
  • 螺旋線是我加的,因為「空間線型 + midas 短板」最典型就是螺旋匝道。不需要的話說一聲就拿掉。
